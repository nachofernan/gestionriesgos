# 2026-09-24 — Rediseño de riesgo/show

Desarrollado en la rama `rediseno/riesgo-show` e integrado en `main`. Las decisiones y su motivo están en
[D-016](../DECISIONES.md#d-016). Este documento sirve de mapa de las piezas, para replicar el diseño
en las otras pantallas de detalle.

## La pantalla

```
┌ encabezado: código · estado · Compartido · Mayor criticidad        [acciones de estado] [⋯ eliminar] ┐
├ ResumenPropuestas (banner: cuántas pendientes, cuántas te tocan, en qué bloque, con anclas)          ┤
├──────────────────────────────── col 8 ───────────────────────┬──────────── col 4 (sticky) ───────────┤
│ FichaRiesgo                                                  │ InfoRiesgo   (Valor)                  │
│ [Planes | Controles | Objetivos]  ← pestañas en JS plano     │ GestionAreas (Gerencias)              │
│   GestionPlanes / GestionControles / GestionObjetivos        │ GestionActualizaciones variante       │
│ ConversacionRiesgo (Mensajes | Archivos)                     │   'timeline' (Actividad)              │
└──────────────────────────────────────────────────────────────┴───────────────────────────────────────┘
```

En mobile el lateral pasa arriba (`order-1`). Las pestañas se manejan con `mostrarFicha()` en
`show.blade.php`. Los links `#planes`, `#controles` y `#objetivos` de otros bloques (por ejemplo los
del banner) cambian de pestaña antes de hacer scroll. Con un bloque en edición (`data-editando`) las
otras pestañas se bloquean con CSS (`:has`).

## Anatomía de un bloque

`x-auditoria.bloque-riesgo` es el contenedor común:

| Slot / prop | Qué es |
|---|---|
| slot por defecto | Lo vigente |
| `accion` | Botón del encabezado (partial `riesgo/show/partials/boton-editar`) |
| `pie` | Barra de edición guardar/cancelar (partial `barra-edicion`), sólo si `editando` |
| `propuestas` | Las tarjetas de lo propuesto, en ámbar punteado, sólo si `hayPropuestas` |
| `modo` / `gerencias` | En edición, la franja que explica qué pasa al guardar |

Del lado del componente, el trait `Riesgo\Show\Concerns\PropuestasEnBloque` provee:

- `modoCambio(Riesgo)`: `directo` / `propuesta` / `doble`. `guardar()` lo usa para decidir si aplica,
  y la vista para el aviso.
- `propuestasDe(Riesgo, $parte)`: las pendientes de esa relación, o `'campos'`, con el eager load que
  necesita la tarjeta.
- `marcasDe()`: la marca sobre la fila vigente ("se propone quitar", "mit. 4 → 6").
- `idsConPropuesta()` / `elementoConPropuesta()`: la guarda que impide tocar un elemento que tiene una
  propuesta pendiente. `agregar()`, `quitar()` y `actualizarMitigacion()` la chequean del lado del
  servidor, y el modal de búsqueda excluye esos ids.
- `proponerPorElemento()`: convierte el diff del bloque en una `Actualizacion` por elemento.

Cada componente pasa a la vista `modo`, `gerencias`, `propuestas`, `marcas`, `bloqueados` y
`diffEnCurso` (el diff de la edición en curso, para previsualizar).

## Propuestas por elemento

Formato de `data` de una propuesta por elemento (una por alta, baja o cambio):

```php
['tipo' => 'cambio',
 'relaciones' => ['controles' => ['agregar' => [12 => ['mitigacion' => 4]]]],   // o 'detach' => [12], o 'actualizar' => [12 => [...]]
 'diff' => ['relaciones' => ['controles' => ['agrega' => [['id' => 12, 'nombre' => '…', 'mitigacion' => 4]]]]]]
```

`Actualizacion::aplicarCambios()` y `RiesgoController::aplicarCambiosActualizacion()` llaman a
`aplicarOperacionesPorElemento()` después de `sync`/`attach`/`detach`. `agregar` usa
`syncWithoutDetaching` (no duplica) y `actualizar` usa `updateExistingPivot` (sólo toca la
mitigación). Borrador y modo directo siguen usando `sync`. Gerencias sigue proponiéndose en bloque.

## Resolver una propuesta

```
tarjeta (x-auditoria.propuesta-pendiente)
  └ partial auditoria.partials.propuesta-acciones → Livewire.dispatch('resolver-actualizacion', {id, accion})
      └ GestionActualizaciones::resolver() → validar/aprobar/rechazar/cancelarActualizacion()  (authorize + voto)
          └ dispatch('riesgo-actualizado') → bloques, Ficha, Valor, banner y Actividad se redibujan
```

La tarjeta decide qué botones mostrar con las mismas policies y condiciones de estado que usaba el
historial. `ResumenPropuestas` cuenta las que el usuario puede resolver con esa misma regla.

## Ficha

`FichaRiesgo` edita nombre, descripción, respuesta, fundamento, tipo, impacto y probabilidad. Valida
en el borde, descarta lo que no cambió y los campos con una propuesta pendiente, y llama a
`Actualizacion::registrarCambioCampos()`. Esa función salió de `GestionActualizaciones::guardar()`,
que ahora también la usa, y decide el estado inicial, la doble validación y si se aplica en el acto.
En borrador el botón lleva a `RiesgoController::edit`.

## Conversación y Actividad

- `ConversacionRiesgo`: pestaña Mensajes (notas, la más nueva primero, `enviar()` autoriza `update`)
  y pestaña Archivos (todos los adjuntos de cualquier actualización del riesgo).
- `GestionActualizaciones` suma `variante` (`completa` | `timeline`). La variante `timeline` excluye
  las notas, marca las pendientes (`pendientesIds`) y abre un modal de detalle (`abrirActividad()`)
  con filtros por tipo y por parte, que sí incluye las notas. El modal de nueva actualización de la
  vista `completa` pasó al partial `actualizaciones/partials/modal-nueva`.

## Valor

`InfoRiesgo` muestra impacto + probabilidad = total, menos `mitigacion_controles` y
`mitigacion_planes` (accessors nuevos de `Riesgo`), igual a residual. Avisa si hay una propuesta
pendiente sobre impacto o probabilidad. Mientras se editan Controles o Planes, muestra el residual
proyectado que esos bloques emiten con `residual-actualizado`.

## Componentes Blade nuevos

`x-auditoria.bloque-riesgo`, `x-auditoria.propuesta-pendiente`, `x-auditoria.modal-buscar` (buscador
para agregar a un bloque, con loading) y `x-auditoria.spinner`.

## Fixes que vinieron con el cambio

- `construirDiff()` de Controles y Planes: un pivot `mitigacion` en null se comparaba contra el valor
  efectivo (la default del control) y generaba un "cambio" fantasma al guardar sin tocar nada. Ahora
  se compara el valor efectivo contra el valor efectivo.
- `valorTotal` de Controles y Planes se refresca en `cargar()`. Antes quedaba el de `mount()` aunque
  impacto o probabilidad cambiaran.
