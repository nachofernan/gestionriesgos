# Actualizaciones — 3 de julio de 2026 (bis)

## Resumen

Dos fixes puntuales sobre el wizard de creación de riesgo agregado en la sesión anterior del mismo día ([2026-07-03](2026-07-03.md)): un error al mostrar el historial de actualizaciones de un riesgo recién creado, y el área que no se autocompletaba como sí lo hace el responsable.

---

## Motivación

Al crear un riesgo con el wizard nuevo y entrar a su vista de detalle, `gestion-actualizaciones.blade.php` tiraba `htmlspecialchars(): Argument #1 ($string) must be of type string, array given`. Además, se detectó que el campo Área no tomaba automáticamente la del usuario logueado al crear, a diferencia del campo Responsable que sí lo hace.

---

## Cambios implementados

### `app/Http/Controllers/Auditoria/RiesgoController.php`

- `store()`: las respuestas del wizard (`probabilidad_respuestas`/`impacto_respuestas`) se guardaban dentro de `data['campos']` de la `Actualizacion` de creación. Esa clave la recorre genéricamente la vista de historial esperando valores escalares (nombre, descripción, impacto, etc.) — al meter ahí dos arrays, rompía el render. Se separaron a `data['respuestas']`, fuera de ese recorrido, sin perder el registro de auditoría.
- `store()`: `area_id` ahora se autocompleta con el área del usuario logueado (`Auth::user()->area_id`) si no se eligió ninguna, igual que ya hacía `user_id`.

### `resources/views/auditoria/riesgo/create.blade.php`

- El `<select>` de Área ahora preselecciona `auth()->user()->area_id`, igual que ya hacía el de Responsable con `auth()->id()`.
