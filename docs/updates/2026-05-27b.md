# Actualizaciones — 27 de mayo de 2026 (b)

## Resumen

Implementación de modales de resumen para todos los elementos relacionados en las vistas `show` del módulo. En lugar de navegar directamente al elemento hijo al hacer clic, se abre un modal Alpine con los datos principales y un badge de estado. El botón para navegar al detalle completo solo se muestra si el usuario tiene permiso de `view` sobre ese elemento.

---

## Sistema de modales en vistas show

### Problema resuelto

En las vistas de detalle (`show`) de cada entidad, los elementos relacionados listados (por ejemplo, los controles de un riesgo, o los riesgos de un plan de acción) redirigían directamente al `show` del elemento hijo al hacer clic. Esto causaba dos problemas:
- UX innecesariamente disruptiva para consultas rápidas.
- Errores 403 cuando el usuario tenía permiso para ver el padre pero no el hijo.

### Solución implementada

Cada elemento relacionado abre un modal Alpine con un resumen (estado, descripción, métricas principales, área). El footer del modal contiene el botón "Ver X completo" con `x-show="modal.puede_ver"`, que solo aparece si el usuario tiene permiso de `view` según la policy correspondiente.

El campo `puede_ver` se computa server-side en el render de la vista mediante `auth()->user()->can('view', $model)` y se embebe en el JSON de cada ítem usando `@js($data)`.

## Partial reutilizable: modal de riesgo

**Archivo nuevo:** `resources/views/auditoria/partials/modal-riesgo-detalle.blade.php`

Partial Alpine genérico para el modal de detalle de un riesgo. Requiere `x-data="{ modalDetalle: null }"` en un ancestro. Muestra: tipo de riesgo, nombre, estado badge, descripción, valor total y residual, impacto, probabilidad, área. Footer con `x-show="modalDetalle.puede_ver"`.

Reutilizado en: `control/show`, `planaccion/show`, `objetivo/show`, `tarea/show`.

## Livewire: componentes de gestión en riesgo/show

### `GestionControles`

**PHP** (`app/Livewire/Auditoria/Riesgo/Show/GestionControles.php`):
- `cargar()`: eager load `controles.estado`, `controles.area`. Agrega a `$seleccionados`: `descripcion`, `estado`, `estado_color`, `area`, `puede_ver`, `url`.
- `agregar()`: usa `Control::with(['estado', 'area'])->find()`, mismos campos.

**Blade** (`resources/views/livewire/auditoria/riesgo/show/gestion-controles.blade.php`):
- Root div: `x-data="{ modalDetalle: null }"`.
- Filas en modo lectura: `@click="modalDetalle = @js($ctrl)"` + `cursor-pointer`.
- Badge de estado visible en modo lectura.
- Modal Alpine al final: nombre, estado, descripción, dos cards (mit. default / en este riesgo), área, footer `x-show="modalDetalle.puede_ver"`.

### `GestionObjetivos`

**PHP** (`app/Livewire/Auditoria/Riesgo/Show/GestionObjetivos.php`):
- `cargar()`: eager load `objetivos.estado`, `objetivos.area`. Agrega: `descripcion`, `estado`, `estado_color`, `area`, `fecha_objetivo`, `estrategico`, `anticorrupcion`, `puede_ver`, `url`.
- `agregar()`: usa `Objetivo::with(['estado', 'area'])->find()`.

**Blade** (`resources/views/livewire/auditoria/riesgo/show/gestion-objetivos.blade.php`):
- Modal Alpine: nombre, estado, badges Estratégico/Anticorrupción, descripción, fecha objetivo, área, footer `x-show="modalDetalle.puede_ver"`.

### `GestionPlanes`

**PHP** (`app/Livewire/Auditoria/Riesgo/Show/GestionPlanes.php`):
- `cargar()`: eager load `planesAccion.estado`, `planesAccion.area`, `planesAccion.tareas`. Agrega: `descripcion`, `estado`, `estado_color`, `area`, `avg_avance`, `tareas_count`, `vencimiento`, `puede_ver`, `url`.
- `agregar()`: `PlanAccion::with(['estado', 'area', 'tareas'])->find()`.
- `render()`: `$planesConTareas` carga `tareas.estado`, `tareas.area`, `tareas.user`.

**Blade** (`resources/views/livewire/auditoria/riesgo/show/gestion-planes.blade.php`):
- Root: `x-data="{ modalPlan: null, modalTarea: null }"`.
- Nombre del plan: `<button @click="modalPlan = @js($plan)">` en modo lectura.
- Tareas anidadas: cada una construye `$tareaData` con `'puede_ver' => auth()->user()->can('view', $tarea)` y `@click="modalTarea = @js($tareaData)"`.
- Dos modales Alpine: plan (footer `x-show="modalPlan.puede_ver"`) y tarea (footer `x-show="modalTarea.puede_ver"`).

## Permiso: ocultar botón de navegación

El campo `puede_ver` (boolean, computado server-side) controla la visibilidad del footer de cada modal mediante `x-show`. Si el usuario no tiene permiso `view` sobre el elemento, el botón "Ver X completo" no aparece — el usuario puede ver el resumen pero no navegar al detalle (lo que causaría un 403).

Archivos con `x-show` en footer de modal:

| Archivo | Variable de modal | Condición |
|---|---|---|
| `modal-riesgo-detalle.blade.php` | `modalDetalle` | `x-show="modalDetalle.puede_ver"` |
| `gestion-controles.blade.php` | `modalDetalle` | `x-show="modalDetalle.puede_ver"` |
| `gestion-objetivos.blade.php` | `modalDetalle` | `x-show="modalDetalle.puede_ver"` |
| `gestion-planes.blade.php` | `modalPlan` | `x-show="modalPlan.puede_ver"` |
| `gestion-planes.blade.php` | `modalTarea` | `x-show="modalTarea.puede_ver"` |
| `gestion-tareas.blade.php` | `modalDetalle` | `x-show="modalDetalle.puede_ver"` |
| `tarea/show.blade.php` | `modalPlan` | `x-show="modalPlan.puede_ver"` |
| `objetivo/show.blade.php` | `modalTarea` | `x-show="modalTarea.puede_ver"` |
